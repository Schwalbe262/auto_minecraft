# Auto Valley

Society: Sunlit Valley용 **클라이언트 전용** 농장 보조 모드입니다. Minecraft **1.20.1**, Forge **47.4.0**, Society **4.1.4**의 설치된 동작을 기준으로 개발했습니다. 내 클라이언트에 설치하며 서버 설치는 필요하지 않습니다.

## 시작

1. [Releases](https://github.com/Schwalbe262/auto_minecraft/releases)에서 `autovalley-0.1.2.jar`를 받아 해당 CurseForge 인스턴스의 `mods` 폴더에 넣고 게임을 재시작합니다. 이전 Auto Valley JAR는 백업한 뒤 `mods`에서 빼서 한 버전만 남기세요.
2. 서버에 접속한 뒤 **Ctrl+F8**로 설정을 엽니다. 처음 접속하거나 재접속하면 항상 전체 OFF입니다.
3. 아래 초기 등록을 마치고 화면을 닫은 뒤 **F8**로 시작합니다. **Pause**는 긴급 정지입니다.

백그라운드 실행은 기본 켜짐입니다. Alt+Tab으로 다른 프로그램을 사용해도 자동화가 유지되며, 다른 앱의 키보드·마우스를 조작하거나 가로채지 않습니다. 게임 안에서 직접 이동·클릭하면 일시정지합니다. 설정에서 백그라운드를 끄면 창 전환 시에도 중지합니다. 다시 시작하려면 F8을 누르세요. 키는 Minecraft 조작 설정의 Auto Valley 항목에서 바꿀 수 있습니다. 경유지 등록 키는 기본 미지정이며, 필요하면 직접 지정하세요.

## 초기 등록

- **괭이:** 사용할 괭이를 핫바에서 선택하고 설정의 괭이 등록을 누릅니다.
- **주변 후보:** 등록 탭에서 탐색합니다. 주변 로드된 블록만 탐색하므로 다른 장소는 직접 이동한 뒤 다시 탐색하세요.
- **밭 N개:** 토마토를 바라본 뒤 설정을 열어 첫 모서리와 두 번째 모서리를 지정합니다. 밭 개수는 두 개로 제한하지 않습니다. 줄 위의 토마토까지 들어가도록 위아래 높이를 포함하세요. 밭 하나의 범위는 최대 32,768칸이며, 자동 제안 영역도 확인 후 저장해야 합니다.
- **창고:** 토마토 저장소는 등급 구분 없이 토마토라는 품목만 지정합니다. 여러 등급을 한 통에 보관할 수 있고 예전 등급 등록값은 제한으로 사용하지 않습니다. 와인은 툴팁에 표시된 **숙성 나이(0년, 1년…)**를 입력합니다. 내부적으로 Vinery 고유 시계와 생산군을 연결하므로 기존 와인이 나이를 먹어도 분류가 유지됩니다. 수면으로 빨리 넘긴 게임 날짜를 와인 나이로 사용하지 않습니다. 각 상자의 내용물을 열어 확인한 뒤 등록하세요. 큰 상자는 양쪽이 정상 로드된 경우에만 하나로 취급합니다.
- **설비:** 와인통·절임통 하나를 선택하고 같은 종류의 연결된 묶음을 미리 본 뒤 일괄 등록할 수 있습니다. 개수·범위·부분 탐색 경고를 확인하세요. 스마트 배송상자와 침대는 각각 등록합니다. 저장통의 내용물 분류는 추측해서 일괄 등록하지 않습니다.
- **폐기:** 서버의 TrashSlot이 지원되면 장소 등록 없이 인벤토리에서 썩은 토마토만 처리합니다. 지원되지 않는 환경에서만 등록 위치·방향을 사용하는 기존 투척 방식이 필요합니다. 다시 주워지는 곳에는 투척 지점을 만들지 마세요.
- **이동 경로:** 개발 버전은 실제 지형으로 길을 찾으므로 경유지가 필수는 아닙니다. 기존 작업장 좌표를 그대로 사용하며 경유지는 선택적 힌트입니다. 설정에서 힌트를 끄거나 이전 경유지 제한 방식으로 되돌릴 수 있습니다. 공개 0.1.2 JAR에는 이 변경이 포함되지 않습니다.

등록 후에는 먼저 기능 하나씩 켜서 경로와 분류를 확인하세요. F8 재개는 현재 위치·상자·인벤토리를 다시 확인합니다. 상자 안에서 중지했다면 직접 상태를 확인하고 닫은 뒤 재개하세요.

와인 저장통은 미래 생산분도 예약할 수 있습니다. 입력 `0`은 올해 만든 와인, `+1`은 내년에 새로 만들 와인, `+2`는 그다음 해 새 생산분입니다. 예를 들어 현재 8번 통을 `0`, 9번을 `+1`, 10번을 `+2`로 등록하면, 1년 뒤 8번은 기존 1년차를 유지하고 새 0년차는 9번에 들어갑니다. 실제 통 번호·위치를 확인해 각각 등록해야 하며, 사진만으로 좌표나 내용물을 추정하지 않습니다.

## 한 번 실행과 직접 플레이 기록

### 좌표 길찾기 (개발 버전)

좌표 설정 화면에서 이름과 X/Y/Z를 입력합니다. **이동만**은 발 위치이고, **시설**은 상자·통·침대 등 대상 블록의 좌표입니다. 시설 후보는 작업 등록과 분리하여 저장합니다. 미로드 시설은 먼저 확인하러 이동하고, 실제 종류와 보관 품목을 확인한 뒤 등록하세요. 이동 원샷은 물건을 옮기거나 다른 작업을 시작하지 않고 도착하면 OFF가 됩니다.

멀리 떨어진 작업장은 확인된 지형을 따라 이동하며 새로 로드된 구간으로 길을 이어 찾습니다. 걷기·계단·반블록·나무문과 검증된 한 칸 오르기를 지원합니다. 농지/작물 위 점프, 수영, 위험한 낙하, 길을 만들기 위한 블록 파괴·설치, 다른 차원 이동은 하지 않습니다. 미로드 지형이나 자원 한도 때문에 경로를 확인하지 못한 경우는 물리적으로 길이 없다는 증명과 구분합니다.

일반 이동이 막히면 제한적으로 우회한 뒤 해당 기능을 보류하고 다른 가능한 기능을 진행합니다. 재시도 간격은 기본 60초에서 반복 실패 시 최대 5분까지 늘어납니다(정상 20틱/초 기준). 보류만으로 작업을 완료하거나 생산일을 넘기지 않습니다. 미확인 아이템 조작·미완료 재식재 등 기존 안전 정지는 유지합니다. 탐색 중/청크 대기/우회/보류 상태는 HUD에 표시합니다. F8 OFF는 이동과 탐색을 취소하고, 재개하면 현재 위치에서 다시 계산합니다.

### 작업 실행·기록

**Ctrl+F8 → 실행·기록**에서 선택합니다.

- **한 번 실행:** 선택한 작업만 처리하고 종료합니다. 와인은 전체 랙의 공통 예정일과 준비 상태를 확인한 뒤 필요한 재료를 가져와 수거·투입합니다. 일부 통만 먼저 완성됐다고 별도로 방문하지 않습니다. 수확·보관·판매·수면으로 자동 전환하지 않으며, 공간이나 경로가 부족하면 이유를 표시하고 멈춥니다. 선택한 기능을 이번 실행에만 허용하고 평소 ON/OFF 설정은 바꾸지 않습니다. 생산의 날짜 쿨타임은 유지합니다. 개발 중인 **벌목·장작**은 아래에 설명한 재식재·제작·보관·베리 배송을 하나의 작업으로 수행합니다.
- **기록 시작:** 자동화를 멈추고 직접 플레이를 관찰합니다. 이동·시선·선택 아이템, 우클릭 대상, 상자 조작 의도와 서버 상태 응답을 저장합니다. 기록 중 Ctrl+F8을 열어도 계속 기록되며, **기록 종료·저장**에서 이름을 입력합니다.
- **전달:** 인스턴스의 `config/autovalley/recordings/recording-이름-….jsonl` 파일을 전달하면 동작 분석에 사용할 수 있습니다. 채팅·서버 주소·플레이어 ID·인증 정보·원본 NBT는 수집하지 않습니다. 좌표·재고는 포함되므로 공개 GitHub에 올리지 마세요.
- 기록은 분석용이며 자동 재생이나 자동 업로드가 없습니다. 녹화 중 자동 작업 시작은 거부됩니다. 연결 종료나 기록 한도 도달 시 수집을 멈추고 파일을 보존합니다. 비정상 종료 뒤에는 같은 폴더의 `pending-….jsonl`에 마지막으로 디스크에 반영된 기록이 남습니다.

### 인벤토리 초과 수확

인벤토리가 가득 차도 수확을 계속하는 옵션은 기본 켜짐입니다. 서버의 우클릭 확인과 작물 상태 변화로 수확을 판정하며 바닥 수확물 수량이나 운반 완료를 추적하지 않습니다. 보관·폐기는 실제 인벤토리의 아이템을 대상으로 합니다. 단독 수확 실행은 수확 후 멈추므로 보관 작업은 별도로 실행해야 합니다.

## 자동화 동작

| 기능 | 기준 |
|---|---|
| 수확 | 괭이를 들고 익은 `tomatoes` / `tomatoes_on_rope`만 우클릭, 등록된 모든 밭과 누락 작물 재확인 |
| 폐기 | TrashSlot의 단일 슬롯 처리로 `farmersdelight:rotten_tomato`만 폐기하고 서버 응답으로 삭제 확인 |
| 토마토 보관 | 토마토만 든 등록 저장소에 등급 제한 없이 보관; 열린 통 안의 호환 스택부터 채우는 기본 게임 전송 사용 |
| 생산 재료 | 보충하러 갈 때 등급별 총수량을 세어 가장 많은 등급으로 한 번에 확보; 가져온 재료를 쓴 뒤 다시 비교하며 실시간 잔량 균등화는 하지 않음 |
| 와인 | 먼저 재료 배정, 3개씩 투입, 완성품 수거 후 숙성 나이별 보관 |
| 병조림 | 와인에 배정하고 남은 토마토 사용; 기본 5개, 업그레이드 통은 3개 |
| 배송 | 토마토 병조림과 소나무 타르만 스마트 배송상자 입력으로 이동 |
| 잉여 와인 배송 | 같은 나이에 등록된 저장통 전부가 64개 스택으로 가득 찬 것을 새로 확인했을 때만 소지 중 잉여분 판매; 저장 와인은 꺼내 팔지 않음 |
| 수면 | 할 수 있는 활성 작업을 마친 뒤 게임 시간 18:35부터 시도; 실제 다음 날 전환 확인 |
| 벌목·장작 (개발 버전) | 기본 OFF; 등록한 2×2 가문비나무 벌목·재식재, 장작 제작과 남은 원목 보관, 모스베리 배송 |

와인은 수령 수량을 별도로 추적하거나 미회수 산출물 의무를 만들지 않습니다. 절임통은 수령 확인과 미회수 경고를 유지하며, 두 생산 모두 서버 조작 응답·재료 감소·설비 상태 확인을 생략하지 않습니다.

### 날짜 단위 쿨타임

실시간 초가 아니라 **게임 날짜**로 다음 예정일을 저장합니다. 와인 기본 주기는 **6일**, 절임통은 **3일**입니다. 토마토 기본 **1일은 상태 확인 간격**이며, 하루마다 반드시 다시 익는다는 뜻이 아닙니다. 일반 토마토는 성장 단계와 비료에 따라 실제 수확 간격이 달라집니다. 확인한 밭의 주기에 맞춰 설정에서 1~28일로 조절하세요.

수확 직후 작물이 미숙 상태로 돌아오는 것은 정상입니다. 밭 일부의 성장 시점이 엇갈리면 매일 조금씩 익는 것처럼 보일 수도 있습니다. 약한 비료 농지에서 확인한 2일 주기를 사용하는 경우, 마지막 수확부터 2일 뒤로 밭의 다음 날짜를 맞추면 하루 먼저 익은 소량을 수확하러 따로 가지 않습니다. 다른 비료·새 밭에 같은 주기를 무조건 적용하지는 마세요.

와인은 통마다 별도 방문하지 않고 **등록된 랙 전체를 한 주기**로 처리합니다. 기존 통들의 예정일이 엇갈리면 가장 늦은 예정일로 맞추며, 일부 통이 아직 생산 중이면 전체가 준비될 때까지 이동·재고 조사 없이 기다립니다. 작업 도중 중단하면 미완료 목록을 저장해 이어서 처리하고, 전체 투입을 마친 마지막 게임 날짜를 기준으로 다음 주기를 잡습니다. 한 게임 일이 현실 20분인 환경에서 매일 바로 자면 6일은 약 1시간, 자지 않으면 약 2시간입니다.

예정일 전에는 해당 작업을 건너뜁니다. 예정일에도 실제 성장·완료 상태를 확인하며 미완성 설비를 무작정 클릭하지 않습니다. 새날의 성장·설비 갱신 시간을 기다린 뒤 판단합니다. 일정은 재접속 후에도 유지됩니다. 직접 설비를 다시 채우거나 구조를 바꿨다면 설정의 **일정 초기화**로 다시 관찰하게 할 수 있습니다.

### 빠른 수확

실제 작물 배치를 기준으로 긴 방향의 고정된 줄을 왕복합니다. 스프링클러·미숙한 중심 작물 때문에 생기는 빈 구간은 해당 구간을 떠나기 전에 보완합니다. 수확 응답 후에도 주변에 익은 토마토나 위쪽 덩굴이 남으면 가까운 범위부터 추가 수확하고 다음 구간으로 이동합니다. 예상 범위만으로 수확 완료 처리하지 않으며, 응답을 기다리는 동안에는 같은 줄의 바로 다음 지점으로만 이동합니다.

넓고 평평한 길에서는 안전을 확인한 대각선 경로를 사용하고 시선을 점진적으로 회전합니다. 문·계단·막힌 모서리는 기존 경로를 유지합니다. 우클릭 순간의 정확한 조준과 서버 응답 확인은 생략하지 않습니다.

설정에서 속도 측정을 준비한 뒤 닫고 F8로 시작합니다. 실제 이동이 있는 걷기 4회와 달리기 4회를 비교하고, 확인된 수확과 획득 결과가 정상일 때만 더 빠른 모드를 적용합니다. 측정할 익은 작물이 부족하면 다음 수확까지 이어집니다. 농지 위로 점프하지 않습니다.

### 벌목·장작 설정 (개발 버전)

이 항목은 개발 소스에 추가된 기능이며 공개 0.1.2 JAR에 포함됐다는 뜻이 아닙니다. **토마토는 계속 괭이 우클릭 전용**입니다. 채굴 예외는 별도로 등록한 2×2 가문비나무의 확인된 밑동에만 적용하며, 토마토·다른 수종·건축용 원목을 일반적으로 파괴하는 기능이 아닙니다.

1. **Ctrl+F8 → 밭·벌목 구역 → 벌목 구역… → 새 벌목 구역 등록 / 이어서**로 들어갑니다. 심어진 2×2 가문비나무의 북서쪽 묘목 또는 밑동을 바라보고 설정을 연 뒤, **조준한 식재 칸을 북서 모서리로**를 누르고 이름을 저장합니다. 같은 높이에서 동쪽·남쪽으로 이어지는 네 칸 모두 로드된 가문비나무 묘목·원목이어야 합니다. 필요한 구역을 각각 등록하며 목록에서 수정·등록 해제가 가능합니다. 토마토밭이나 다른 벌목 식재 칸과 겹칠 수 없습니다.
2. **도끼·벌목 설정…**에서 사용할 네더라이트 도끼를 선택한 뒤 등록합니다. 괭이와 다른 단축바 칸을 사용해야 하며 내구도는 2 이상이어야 합니다. 도구가 바뀌거나 실제 벌목 범위를 안전하게 확인하지 못하면 중지합니다.
3. **시설 등록**에서 일반 상자·통을 **장작·원목 보관함**으로, 바닐라 제작대를 **벌목용 제작대**로 등록합니다. 보관함은 `minecraft:spruce_log`와 `meadow:fire_log` 전용이며 내용물을 직접 확인해야 합니다. 기존 스마트 배송상자도 필요합니다. 세 작업 장소까지 실제로 통행 가능한 길이 있어야 하며, 지형 길찾기 모드에서는 연결 경유지가 필수가 아닙니다.
4. 먼저 **실행·기록 → 한 번 실행 → 벌목·장작**으로 등록 구역의 현재 가능한 작업을 한 차례 실행할 수 있습니다. 반복하려면 기능 화면의 **벌목·장작**을 켜고 설정을 닫은 뒤 F8로 시작합니다. 새 설정과 기존 설정에서 빠져 있던 벌목 기능은 모두 기본 OFF이며, 등록·설정 저장만으로 시작되지 않습니다. F8 일시정지와 Pause 긴급 정지는 그대로 적용됩니다.

완전한 작업에는 벌목, 빈 네 식재 칸 복구, 부산물 정리, 제작·보관과 베리 배송이 포함됩니다. 장작은 등록 제작대에서 **가문비나무 원목 6개 → `meadow:fire_log` 1개**로 만듭니다. 판자를 만드는 기능이 아닙니다. 서버에서 동기화된 정확한 제작법을 확인하며, 클라이언트 레시피북에 항목이 없으면 일반 인벤토리 클릭으로 재료를 배치합니다. 매 클릭의 전체 슬롯·커서 응답을 확인하고 남은 원목은 원래 칸에 돌려놓습니다. 다른 원목 종류가 함께 있으면 제작 재료가 섞이지 않도록 멈춥니다. 만든 장작과 제작에 쓰이지 않은 원목은 목재 보관함에 넣고, 소지한 `society:mossberry`는 스마트 배송상자에 넣습니다. 이는 배송 투입이며 즉시 대금 지급을 확인한다는 뜻은 아닙니다. 일반 병조림·타르 배송의 허용 품목을 다른 베리 전체로 넓히지 않습니다.

벌목 전용 이동에는 동서남북으로 인접한 한 칸의 **실제 지면 높이가 정확히 한 블록 높은 경우**만 오르는 예외가 있습니다. 등록 범위 안의 지면·몸통 통과 공간을 실제 게임 지형으로 확인하고, 활성 벌목 작업에서만 사용합니다. 출발점에 정렬한 뒤 점프 입력은 한 번만 보내며, 착지 높이와 중앙 위치에서 서로 다른 두 틱 동안 지면에 서 있는 것을 확인하기 전에는 도착 처리하거나 작업하지 않습니다. 중단·시간 초과된 구간의 점프는 F8 재개로 자동 재발사하지 않습니다. 지형 길찾기는 별도로 검증된 일반 한 칸 오르기를 사용할 수 있지만, 수확 응답 확인 중 점프와 농지·작물 위 점프는 계속 금지합니다. 등록된 테스트 환경에서 오르기·벌목·재식재와 이후 보관까지 단계별 실게임 확인을 마쳤습니다. 이는 임의 지형이나 장시간 무중단 동작을 보장하는 검증은 아닙니다.

반복 조건은 다음 세 가지입니다.

- **등록 나무 전체 성장 후**(기본): 등록 나무가 모두 성장했을 때 새 벌목 배치를 시작합니다. 빈 식재 칸 복구와 남은 생산물 정리는 별도로 처리할 수 있습니다.
- **예정일 + 성장 확인**: 마지막 완료일부터 설정한 게임 날짜 간격이 지난 뒤 현재 성장한 나무를 처리합니다. 날짜 간격은 1~28일이며 기본 1일입니다. 날짜가 지났다고 묘목을 베지 않습니다.
- **한 번 실행 전용**: 연속 자동화에서는 새 벌목을 시작하지 않습니다. 실행·기록의 한 번 실행으로 직접 시작하세요. 명시적 한 번 실행은 반복 모드의 대기 조건 대신 현재 성장·재식재 상태와 안전 조건을 확인합니다.

**확인 간격**은 기본 60초이며 1~1,200초, 0.05초 단위로 설정합니다. 이는 상태 확인 간격이지 나무가 성장한다고 가정하는 시간이 아닙니다. **예비 묘목**은 재식재 뒤 추가로 남길 최소 수량으로, 기본 0개·설정 범위 0~2,304개입니다. 모든 등록 식재 칸을 복구한 뒤 그 수량을 침해하지 않는 여분 묘목 스택과 `twigs:twig`만 TrashSlot으로 처리합니다. 스택 단위이므로 설정값보다 더 남을 수 있습니다. 바닐라 막대기는 폐기하지 않습니다.

빈 단축바가 없으면 묘목을 쓰기 위해 허용된 다른 칸을 잠시 빌리고 원래 아이템을 복원합니다. 괭이·벌목 도끼 칸은 빌리지 않습니다. 미완료 구역, 재식재 진행과 임시 단축바 복원 정보는 저장되며 F8·재접속·일정 초기화로 없어지지 않습니다. 미완료 배치가 있으면 구역·도끼·벌목 설정 편집이 잠깁니다. 중단 뒤 인벤토리를 바꿨거나 서버 응답이 불분명하면 임의로 교환을 재실행하지 않고 확인을 요구할 수 있습니다.

나무 한 그루에서 묘목이 부족하게 나오면 빈 2×2 구역을 재식재 대기 목록에 남기고 **현재 배치의 다른 미처리 등록 나무**로 넘어갑니다. 묘목이 모이면 먼저 비워 둔 구역부터 돌아가 심습니다. 빈 네 칸을 채울 묘목이 모두 확보되기 전에는 일부만 먼저 심지 않으며, 이미 완료한 나무를 이 목적으로 다시 베지는 않습니다. 직접 베어 비워진 현재 배치의 구역도 재개할 때 실제 블록을 확인해 대기 목록에 보존합니다.

다른 미처리 나무도 없고 추가 도착 대기 뒤에도 묘목이 부족하면 벌목만 재료 대기로 남깁니다. 조작 응답·인벤토리·임시 단축바 상태가 안전하게 확인된 **연속 모드**에서는 다른 작업과 수면을 진행할 수 있습니다. 묘목이 보충되면 다른 작업이 안전하게 끝나는 경계에서 재식재를 우선 재확인합니다. **한 번 실행**에서는 벌목만 대기하며 다른 기능을 실행하거나 완료로 처리하지 않습니다. 일부만 작은 나무로 자란 구역, 건축 변경, 불분명한 서버 응답은 이 재료 부족 예외에 포함되지 않습니다.

**벌목 기능을 OFF하면 미완료 벌목 목록은 보존하고 다른 활성 기능을 실행할 수 있습니다.** 단, 미확인 서버 조작·임시 단축바 복원·미회수 산출물은 먼저 해결해야 하며, OFF로 이런 안전 조건을 지우지는 않습니다. 다시 ON하면 진행 중인 다른 작업이 끝나는 안전한 경계에서 벌목을 우선 재개합니다. 다른 기능의 **한 번 실행**에 벌목을 끼워 넣지는 않으며, 벌목을 명시적으로 한 번 실행하면 저장된 ON/OFF 설정을 바꾸지 않고 미완료 벌목을 이어갑니다.

이 영속 상태와 좌표 설정을 보호하기 위해 개발 버전은 **프로필 형식 4**를 사용합니다. 유효한 형식 1·2·3은 검증 후 메모리에서 올리고 실제 저장 전에는 원본 파일을 덮어쓰지 않습니다. 형식 4를 지원하지 않는 구버전은 저장된 설정을 거절합니다. 구버전을 쓰려고 형식 숫자나 미완료 상태를 수동으로 지우지 마세요.

## 중지 조건과 현재 범위

일반 공격·블록 파괴 입력과 패킷은 실행 중 차단합니다. 개발 버전의 예외는 **벌목 작업에서 검증한 등록 가문비나무 밑동 채굴**뿐이며, 토마토 수확에는 좌클릭을 사용하지 않습니다. 인벤토리 이동은 서버의 전체 상태 응답을 확인한 뒤 이어갑니다. 응답이 불분명한 생산·벌목 조작은 자동 재실행하지 않습니다.

저장 공간 부족, 미등록 와인 연도, 접근할 수 없는 경로, 낮은 체력·허기, 도구 문제는 상태 표시와 함께 중지 또는 대기합니다. 먹기·수리·전투·일반 건축·텔레포트는 포함하지 않습니다. 벌목의 블록 설치는 등록한 빈 식재 칸에 가문비나무 묘목을 다시 심는 경우로 제한합니다. 서버의 수면 조건이나 다른 플레이어의 상태 때문에 하루가 넘어가지 않을 수 있습니다.

이 릴리스는 초기 버전입니다. 실제 Society 4.1.4 클라이언트에서 모드 로드·한국어 설정 화면·연속 작물 묶음 탐색을 확인했습니다. 위치 등록, 생산 주기와 배송 전체 동작은 아직 실서버 검증이 필요합니다. 다른 모드팩 버전이나 서버 설정은 동작이 다를 수 있습니다.

## 빌드와 설치 도구

JDK 17을 지정한 뒤 실행합니다. Gradle 8.8과 ForgeGradle 6.0.54를 사용합니다.

```powershell
.\gradlew.bat test build
.\scripts\Install-Mod.ps1 -InstancePath 'C:\path\to\Society Sunlit Valley'
```

설치 스크립트는 인스턴스 버전을 확인하고 기존 Auto Valley JAR만 백업합니다. 실행 중인 게임을 종료하지 않으며, 새 파일은 다음 재시작에 로드됩니다. 제거하려면 게임 종료 후 `mods`의 `autovalley-*.jar`만 다른 폴더로 옮기세요.

빌드·설치·게시 버전은 `gradle.properties`의 `mod_version`을 기준으로 합니다. 설치·게시 스크립트는 JAR 내부 모드 버전도 확인합니다. 게시 도구는 해당 버전의 사전 릴리스를 만들며, 기존 태그나 업로드 파일을 덮어쓰지 않습니다.

설정은 인스턴스의 `config/autovalley/`에 서버·차원·플레이어별 해시 파일명으로 저장됩니다. 이전 설정의 `.bak` 파일을 유지합니다. 서버 주소, 개인 좌표, 월드 데이터는 이 저장소에 포함하지 않습니다.

구조와 검증 사항은 [개발 문서](docs/ARCHITECTURE.md)를 참고하세요.

### 로컬 진단과 백그라운드 테스트

인스턴스의 `config/autovalley/inspect.request` 파일을 만들면 한 번만 관찰하여 `diagnostics.json`을 생성합니다. 인벤토리·주변 시설·작물 묶음 등 로컬 좌표가 포함되므로 공개 저장소에 올리지 마세요. 게임 동작이나 등록 내용은 변경하지 않습니다.

같은 폴더의 `control.request.json`에 `{"command":"start"}` 또는 `{"command":"pause"}`를 넣으면 게임 내부에서 시작/긴급 정지를 요청하고 `control.result.json`에 결과를 남깁니다. 시작은 F8과 동일한 안전 검사를 거치며 설정·상자가 열려 있으면 거부됩니다. 운영체제 키 입력이나 창 활성화는 사용하지 않습니다. 요청 파일은 처리 후 소비됩니다.

추가로 `{"command":"once","feature":"WINE"}`, `{"command":"record_start"}`, `{"command":"record_stop","name":"와인통 채우기"}`를 지원합니다. 한 번 실행은 정확한 기능 이름만 받고, 기록 저장은 1~64자 이름을 받습니다. 알 수 없는 명령·추가 필드·중복 키·1,024바이트 이상 요청은 거부합니다. 시작 요청은 현재 실행 상태를 켜짐으로 유지하므로, 실행 중인 단독 작업을 전체 자동화로 바꾸려면 먼저 중지한 뒤 시작하세요.

개발 버전의 이동 전용 요청은 `{"command":"move_once","x":"12","y":"70","z":"-5"}` 형식입니다(예시 좌표이며 실제 목적지를 입력하세요). 세 좌표는 정수 문자열이어야 합니다. `{"command":"observe_once","name":"저장한 시설 후보 이름"}`은 해당 미검증 후보의 위치만 확인합니다. 두 명령 모두 긴급 정지 우선순위를 지키며, 작업 기능이나 등록 권한을 추가하지 않습니다.
