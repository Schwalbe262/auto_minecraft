# Auto Valley

Society: Sunlit Valley용 **클라이언트 전용** 농장 보조 모드입니다. Minecraft **1.20.1**, Forge **47.4.0**, Society **4.1.4**의 설치된 동작을 기준으로 개발했습니다. 내 클라이언트에 설치하며 서버 설치는 필요하지 않습니다.

## 시작

1. [Releases](https://github.com/Schwalbe262/auto_minecraft/releases)에서 `autovalley-0.1.2.jar`를 받아 해당 CurseForge 인스턴스의 `mods` 폴더에 넣고 게임을 재시작합니다. 이전 Auto Valley JAR는 백업한 뒤 `mods`에서 빼서 한 버전만 남기세요.
2. 서버에 접속한 뒤 **Ctrl+F8**로 설정을 엽니다. 처음 접속하거나 재접속하면 항상 전체 OFF입니다.
3. 아래 초기 등록을 마치고 화면을 닫은 뒤 **F8**로 시작합니다. **Pause**는 긴급 정지입니다.

백그라운드 실행은 기본 켜짐입니다. Alt+Tab으로 다른 프로그램을 사용해도 자동화가 유지되며, 다른 앱의 키보드·마우스를 조작하거나 가로채지 않습니다. 게임 안에서 직접 이동·클릭하면 일시정지합니다. 설정에서 백그라운드를 끄면 창 전환 시에도 중지합니다. 다시 시작하려면 F8을 누르세요. 키는 Minecraft 조작 설정의 Auto Valley 항목에서 바꿀 수 있습니다. 경유지 등록 키는 기본 미지정이며, 필요하면 직접 지정하세요.

## 초기 등록

- **괭이:** 사용할 괭이를 핫바에서 선택하고 설정의 괭이 등록을 누릅니다.
- **주변 후보:** 등록 탭에서 탐색합니다. 주변 로드된 블록만 탐색하므로 다른 장소는 직접 이동한 뒤 다시 탐색하세요.
- **밭 N개:** 토마토를 바라본 뒤 설정을 열어 첫 모서리와 두 번째 모서리를 지정합니다. 밭 개수는 두 개로 제한하지 않습니다. 줄 위의 토마토까지 들어가도록 위아래 높이를 포함하세요. 밭 하나의 범위는 최대 32,768칸이며, 자동 제안 영역도 확인 후 저장해야 합니다.
- **창고:** 토마토는 등급 0(일반), 1(철), 2(금), 3(다이아몬드)별로 등록합니다. 와인은 툴팁에 표시된 **숙성 나이(0년, 1년…)**를 입력합니다. 내부적으로 Vinery 고유 시계와 생산군을 연결하므로 기존 와인이 나이를 먹어도 분류가 유지됩니다. 수면으로 빨리 넘긴 게임 날짜를 와인 나이로 사용하지 않습니다. 각 상자의 내용물을 열어 확인한 뒤 등록하세요. 큰 상자는 양쪽이 정상 로드된 경우에만 하나로 취급합니다.
- **설비:** 와인통·절임통 하나를 선택하고 같은 종류의 연결된 묶음을 미리 본 뒤 일괄 등록할 수 있습니다. 개수·범위·부분 탐색 경고를 확인하세요. 스마트 배송상자와 침대는 각각 등록합니다. 저장통의 내용물 분류는 추측해서 일괄 등록하지 않습니다.
- **폐기:** 썩은 토마토가 안전하게 떨어질 곳을 바라보고, 서 있는 위치와 방향을 등록합니다. 바닥 투척 방식이므로 수거 자석이나 다시 주워지는 장소를 피하세요.
- **이동 경로:** 밭과 지하 창고 사이의 통로·계단·모퉁이에서 순서대로 경유지를 등록합니다. 등록된 작업 구역과 연결 통로 안에서만 이동합니다. 블록 파괴나 점프가 필요한 길은 사용할 수 없습니다.

등록 후에는 먼저 기능 하나씩 켜서 경로와 분류를 확인하세요. F8 재개는 현재 위치·상자·인벤토리를 다시 확인합니다. 상자 안에서 중지했다면 직접 상태를 확인하고 닫은 뒤 재개하세요.

와인 저장통은 미래 생산분도 예약할 수 있습니다. 입력 `0`은 올해 만든 와인, `+1`은 내년에 새로 만들 와인, `+2`는 그다음 해 새 생산분입니다. 예를 들어 현재 8번 통을 `0`, 9번을 `+1`, 10번을 `+2`로 등록하면, 1년 뒤 8번은 기존 1년차를 유지하고 새 0년차는 9번에 들어갑니다. 실제 통 번호·위치를 확인해 각각 등록해야 하며, 사진만으로 좌표나 내용물을 추정하지 않습니다.

## 한 번 실행과 직접 플레이 기록

**Ctrl+F8 → 실행·기록**에서 선택합니다.

- **한 번 실행:** 선택한 작업만 처리하고 종료합니다. 예를 들어 와인은 등록된 설비 중 예정일이 된 통을 확인하고 필요한 재료를 가져와 수거·투입합니다. 수확·보관·판매·수면으로 자동 전환하지 않으며, 공간이나 경로가 부족하면 이유를 표시하고 멈춥니다. 평소 기능 ON/OFF 설정은 바꾸지 않습니다. 날짜 쿨타임도 그대로 지킵니다.
- **기록 시작:** 자동화를 멈추고 직접 플레이를 관찰합니다. 이동·시선·선택 아이템, 우클릭 대상, 상자 조작 의도와 서버 상태 응답을 저장합니다. 기록 중 Ctrl+F8을 열어도 계속 기록되며, **기록 종료·저장**에서 이름을 입력합니다.
- **전달:** 인스턴스의 `config/autovalley/recordings/recording-이름-….jsonl` 파일을 전달하면 동작 분석에 사용할 수 있습니다. 채팅·서버 주소·플레이어 ID·인증 정보·원본 NBT는 수집하지 않습니다. 좌표·재고는 포함되므로 공개 GitHub에 올리지 마세요.
- 기록은 분석용이며 자동 재생이나 자동 업로드가 없습니다. 녹화 중 자동 작업 시작은 거부됩니다. 연결 종료나 기록 한도 도달 시 수집을 멈추고 파일을 보존합니다. 비정상 종료 뒤에는 같은 폴더의 `pending-….jsonl`에 마지막으로 디스크에 반영된 기록이 남습니다.

### 자석과 인벤토리 초과 수확

자석 모드는 기본 켜짐입니다. 인벤토리가 가득 차도 확인된 바닥 수확물을 추적하면서 현재 밭 순회를 마칩니다. 이후 창고 입고·폐기가 서버에서 확인되어야 다음 생산·수면으로 넘어갑니다. 바닥 아이템이 사라졌다는 이유만으로 입고 완료로 처리하지 않습니다. 자석이 없으면 설정에서 끄세요. 단독 수확 실행은 수확 후 멈추므로 보관 작업은 별도로 실행해야 합니다.

## 자동화 동작

| 기능 | 기준 |
|---|---|
| 수확 | 괭이를 들고 익은 `tomatoes` / `tomatoes_on_rope`만 우클릭, 등록된 모든 밭과 누락 작물 재확인 |
| 폐기 | 등록 위치·방향에서 `farmersdelight:rotten_tomato`만 투척 |
| 토마토 보관 | 아이템의 `quality_food.quality`로 등급 분류 |
| 생산 재료 | 등록 창고와 소지품의 등급별 총수량을 집계하고 가장 많은 등급부터 사용; 동률은 낮은 등급 우선 |
| 와인 | 먼저 재료 배정, 3개씩 투입, 완성품 수거 후 숙성 나이별 보관 |
| 병조림 | 와인에 배정하고 남은 토마토 사용; 기본 5개, 업그레이드 통은 3개 |
| 배송 | 토마토 병조림만 스마트 배송상자 입력으로 이동 |
| 잉여 와인 배송 | 같은 나이에 등록된 저장통 전부가 64개 스택으로 가득 찬 것을 새로 확인했을 때만 소지 중 잉여분 판매; 저장 와인은 꺼내 팔지 않음 |
| 수면 | 할 수 있는 활성 작업을 마친 뒤 게임 시간 18:35부터 시도; 실제 다음 날 전환 확인 |

### 날짜 단위 쿨타임

실시간 초가 아니라 **게임 날짜**로 다음 예정일을 저장합니다. 와인 기본 주기는 **6일**, 절임통은 **3일**입니다. 토마토 기본 **1일은 상태 확인 간격**이며, 하루마다 반드시 다시 익는다는 뜻이 아닙니다. 일반 토마토는 성장 단계와 비료에 따라 실제 수확 간격이 달라집니다. 확인한 밭의 주기에 맞춰 설정에서 1~28일로 조절하세요.

예정일 전에는 해당 작업을 건너뜁니다. 예정일에도 실제 성장·완료 상태를 확인하며 미완성 설비를 무작정 클릭하지 않습니다. 새날의 성장·설비 갱신 시간을 기다린 뒤 판단합니다. 일정은 재접속 후에도 유지됩니다. 직접 설비를 다시 채우거나 구조를 바꿨다면 설정의 **일정 초기화**로 다시 관찰하게 할 수 있습니다.

### 빠른 수확

설정에서 속도 측정을 준비한 뒤 닫고 F8로 시작합니다. 실제 이동이 있는 걷기 4회와 달리기 4회를 비교하고, 확인된 수확과 획득 결과가 정상일 때만 더 빠른 모드를 적용합니다. 측정할 익은 작물이 부족하면 다음 수확까지 이어집니다. 농지 위로 점프하지 않습니다.

## 중지 조건과 현재 범위

공격·블록 파괴는 자동화 API에 없으며, 실행 중 해당 입력과 패킷도 차단합니다. 인벤토리 이동은 서버의 전체 상태 응답을 확인한 뒤 이어갑니다. 응답이 불분명한 생산 조작은 자동 재실행하지 않습니다.

저장 공간 부족, 미등록 와인 연도, 접근할 수 없는 경로, 낮은 체력·허기, 도구 문제는 상태 표시와 함께 중지 또는 대기합니다. 먹기·수리·전투·건축·텔레포트는 포함하지 않습니다. 서버의 수면 조건이나 다른 플레이어의 상태 때문에 하루가 넘어가지 않을 수 있습니다.

이 릴리스는 초기 버전입니다. 실제 Society 4.1.4 클라이언트에서 모드 로드·한국어 설정 화면·연속 작물 묶음 탐색을 확인했습니다. 위치 등록, 생산 주기, 수거 자석과 배송 전체 동작은 아직 실서버 검증이 필요합니다. 다른 모드팩 버전이나 서버 설정은 동작이 다를 수 있습니다.

## 빌드와 설치 도구

JDK 17을 지정한 뒤 실행합니다. Gradle 8.8과 ForgeGradle 6.0.54를 사용합니다.

```powershell
.\gradlew.bat test build
.\scripts\Install-Mod.ps1 -InstancePath 'C:\path\to\Society Sunlit Valley'
```

설치 스크립트는 인스턴스 버전을 확인하고 기존 Auto Valley JAR만 백업합니다. 실행 중인 게임을 종료하지 않으며, 새 파일은 다음 재시작에 로드됩니다. 제거하려면 게임 종료 후 `mods`의 `autovalley-*.jar`만 다른 폴더로 옮기세요.

빌드·설치·게시 버전은 `gradle.properties`의 `mod_version`을 기준으로 합니다. 설치·게시 스크립트는 JAR 내부 모드 버전도 확인합니다. 게시 도구는 해당 버전의 사전 릴리스를 만들며, 기존 태그나 업로드 파일을 덮어쓰지 않습니다.

설정은 인스턴스의 `config/autovalley/`에 서버·차원·플레이어별 해시 파일명으로 저장됩니다. 이전 설정의 `.bak` 파일을 유지합니다. 서버 주소, 개인 좌표, 월드 데이터는 이 저장소에 포함하지 않습니다.

구조와 검증 사항은 [개발 문서](docs/ARCHITECTURE.md)를 참고하세요.

### 로컬 진단과 백그라운드 테스트

인스턴스의 `config/autovalley/inspect.request` 파일을 만들면 한 번만 관찰하여 `diagnostics.json`을 생성합니다. 인벤토리·주변 시설·작물 묶음 등 로컬 좌표가 포함되므로 공개 저장소에 올리지 마세요. 게임 동작이나 등록 내용은 변경하지 않습니다.

같은 폴더의 `control.request.json`에 `{"command":"start"}` 또는 `{"command":"pause"}`를 넣으면 게임 내부에서 시작/긴급 정지를 요청하고 `control.result.json`에 결과를 남깁니다. 시작은 F8과 동일한 안전 검사를 거치며 설정·상자가 열려 있으면 거부됩니다. 운영체제 키 입력이나 창 활성화는 사용하지 않습니다. 요청 파일은 처리 후 소비됩니다.

추가로 `{"command":"once","feature":"WINE"}`, `{"command":"record_start"}`, `{"command":"record_stop","name":"와인통 채우기"}`를 지원합니다. 한 번 실행은 정확한 기능 이름만 받고, 기록 저장은 1~64자 이름을 받습니다. 알 수 없는 명령·추가 필드·중복 키·1,024바이트 이상 요청은 거부합니다. 시작 요청은 현재 실행 상태를 켜짐으로 유지하므로, 실행 중인 단독 작업을 전체 자동화로 바꾸려면 먼저 중지한 뒤 시작하세요.
