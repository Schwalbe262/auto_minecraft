# Shared implementation contract

Package: `dev.schwalbe.autovalley`. Java 17, Forge 1.20.1 / 47.4.0.
Root owns native `client/` adapter/runtime, movement safety, build files, documentation and release scripts.
For the terrain-navigation work, navigation owns `navigation/`, `core/Navigation.java` and navigation tests.
Logistics owns `modules/` (including HarvestModule), scheduler/deferred results and corresponding tests.
UI owns `ui/`, languages, coordinate profile types and ProfileStore compatibility. Other core changes require coordination with root.

Core APIs are source of truth in `core/`. Ask root before changing them.
Everything runs once per client tick. Modules never access Minecraft directly: use Context.
Terrain transit is independent of registered action permission. Profile.navigationMode defaults to TERRAIN; useWaypointHints defaults true, but hints only break ties and can be disabled. WAYPOINTS preserves the legacy bounds policy. Native movement requires the active navigator's permitsTransit; general one-use ascents additionally require permitsStepUp for that exact controller edge and native geometry. Ordinary move(jump=true) is forbidden. Preserve registered crop/plot/storage checks and never change loggingRunActive to enable general travel.
Navigation keeps Result MOVING/ARRIVED/BLOCKED; searching and chunk waits are MOVING with separate diagnostics. retryableFailure and failureDestination feed WorkResult.DEFERRED. Engine deferral is per feature with 1200..6000 tick backoff, does not advance deadlines, and never bypasses unresolved actions or logging obligations. CoordinateTravel is a movement-only one-shot, not a work feature. CoordinateDestination drafts are not POIs and require explicit existing registration confirmation after native type checks. Profile schema 4 accepts validated 1..3 in memory without rewriting until save.
Context.checkpoint is a synchronous persistence boundary in the live runtime; compatibility test constructors use an explicit no-op. Mature PRESERVES Use must follow MachineOutputLedger.prepare/checkpoint and separate machine-confirmation/pickup checkpoints. WINE does not create output obligations or wait for counted pickup; historical WINE obligations are checkpointed into resolution history as WINE_PICKUP_TRACKING_DISABLED, not claimed as recovered. This exception does not acknowledge native actions or relax input, machine-state, inventory-transfer or wine-sale reserve checks. Profile schema 2 retains pending preserves output and bounded resolution history; live evidence belongs to SessionState only and is invalidated by manual item interaction or reconnect. F8/reset must never clear the persistent ledger.
ActionPort submit returns ticket; poll outcome on subsequent ticks. One pending action at a time. Do not repeat an action until acknowledged. Cancel requires immediate silence, no cleanup clicks. All world attack/break commands are absent.
Inventory indices 0..35 match Player inventory. Menu ItemSlot.index is actual menu slot, inventoryIndex refers to Player inventory if player=true, -1 otherwise. world.menu() always returns inventory menu when no container is open, with container=false. Only player inventory entries 0..35 are exposed via world.inventory().
SelectHotbar and SwapHotbar allow moving ingredients to held slot without a cursor transaction. QuickMove uses standard shift-transfer and verifies state change. Do not depend on unopened chest contents, server persistentData, or unsynced machine fields.
ConsolidateInventory accepts only a freshly revalidated ProductionMergePlanner plan, with no pending machine output. It is owned-inventory-only; QuickMove remains container-only. Native adapter owns the bounded primitive sequence and returns quantity as actual freed slots, not moved item count. A reposition plan can validly return zero freed slots. No-op attempts must be bounded using a position-independent inventory fingerprint. Cancel sends no cleanup clicks; ActionPort.pauseReason/startRejection fence unresolved late replies and pause all scheduler consumers. Reconnect clears transient layout uncertainty, not persistent output obligations. Native ACK item/cursor snapshots remain RAM-only and must not leak into diagnostics/recordings.
After an exact primitive ACK, a subsequent raw server slot packet may refresh an unrelated baseline slot without advancing the transaction. Every changed slot must exactly match its latest post-ACK packet item; the packet observer's applied client menu is not authoritative evidence. Only production-item additions or exact installed-Vinery passive metadata updates qualify. Source, protected hoe, and the next QUICK_MOVE's entire implicit receiving region remain exact. The borrowed hotbar remains exact except immediately before RESTORE: after both SWAP_OUT and MERGE have their own exact ACKs, a raw-server-proven positive addition of tomato, wine or preserves may fill its now-EMPTY slot (stack limit at most 64). This exception requires a non-direct plan that originally borrowed an occupied slot, with the original borrowed item still exact in the source. The next click remains the same inverse SWAP, restoring the borrowed item and preserving the pickup in the source. No refresh can confirm, repeat, skip, or restore an unacknowledged click; RESTORE still needs its own exact full-menu ACK.
UseBlock(MACHINE) checks actual block state and inventory decrease; products may drop. PRESERVES separately confirms pickup through its durable ledger; WINE has no pickup-count gate. UseBlock(HARVEST) verifies mature state change without tracking ground-output quantities or haul completion; native tomato age=3. UseBlock(OPEN_CONTAINER) waits for new synchronized container. Only normal main hand useItemOn, no air-use fallback. Range and visibility checked by adapter.
Profile POIs are individually confirmed. classifier: production Year for WINE_CHEST; null for TOMATO_CHEST and others. Legacy tomato grade values and desired-layout targets are inert, not permissions or routing rules. Tomato warehouses accept only the tomato commodity, with mixed grades allowed; actual per-grade stock still determines production input. Native stacking never combines incompatible grades/tags. Wine cohort restrictions are unchanged. Farms are two corner inclusive bounds (include vines at both heights), cap volume 32768. Waypoints record walkable feet positions. They form approved corridors only in legacy WAYPOINTS mode; TERRAIN treats them as optional hints. Poi DISPOSAL marks player standing position when registered, not a block to interact with.
Production grade choice is batch-based, not live balancing. Use carried ingredients before another stock survey; a supply trip freshly counts actual grades and allocates the largest total, then keeps that batch while usable. Neither a short cache TTL nor grade crossover should trigger a trip while carried material remains usable. Source reopen and native transfers still verify actual contents. Storage visit ordering completes each same-kind face-adjacent component before visiting the next; it grants no new registrations or movement permissions.
Wine scheduling uses one durable whole-rack cycle, not independent due-machine trips. Legacy registration deadlines migrate to their maximum. After a bounded dawn-update grace, a due cycle opens the registered rack without an all-ready preflight. Persist each remaining member until an actual native refill ACK or an explicit skipped-member record (position, reason, game day). Loaded still-working/missing/wrong-type blocks and removed registrations may be skipped before a native use at a clean action boundary; malformed state, unloaded terrain and unresolved native/target-scoped action fences are not completion or skip evidence. Unloaded members use ordinary navigation/observation. Manual stop/reconnect retains pending members and skipped history without resending confirmed members. Completing a mixed or entirely skipped pass advances the original scheduled date by whole configured cycles (normally six game days) to the first future boundary, not the latest actual feed date. Individual successful-feed dates remain actual ACK audit; skipped members never receive fabricated feed dates or next-day catch-up trips. Explicit schedule reset and clock rollback reset both per-target dates and the global cycle; storage wine-age classification is a separate clock and remains unchanged.
Orchard harvesting retains Feature.STARFRUIT for saved toggles and currently supports registered starfruit masks. It is an independent priority-80 routine, not a travel detour. Each due registered patch is inspected regardless of player distance; only loaded native ripe fruit receives use. Initially unloaded registered positions are approached for observation, never treated as missing or expanded to unregistered trees. Each patch's confirmed harvest is stored before starting the next patch. Completed clean inspection/storage checkpoints orchard:<patch-id> to the next game day; this is an inspection frequency, not an assumed native growth period. Incomplete patches retain same-day scoped retry backoff without a fabricated daily completion and cannot monopolize the scheduler ahead of sleep. Native fruit/door/storage receipts, cursor safety and frozen registration/store identity remain required. Navigation.pendingInteractionOutcome is read-only access to the active navigator's own door ticket, not a general action or movement permit.
Harvest prioritizes 50; logistics 10..40; wine 60 before preserves 70; orchard 80; sleep 100. A BUSY module owns the scheduler until IDLE/BLOCKED, or cancellation. IDLE means nothing actionable, BLOCKED is user-actionable failure and prevents automatic sleep that cycle. Resource shortages in continuous mode and processing machines are IDLE, not BLOCKED. An unfunded eligible refill in one-shot mode is BLOCKED and must remain retryable on the same day. Disabled modules receive no tick and any active module is cancelled on toggle. Sleep time uses dayTime modulo 24000 >=12584, actual next day observed.
Client facade for UI (root will implement): `ClientRuntime.instance()`, `.profile()`, `.world()`, `.status()` string, `.running()` boolean, `.toggle()`, `.pause(String)`, `.saveProfile()`, `.toggleFeature(Feature)`, `.startCalibration()`; `openSettings()` from root handles GUI. UI entry `new ValleyScreen()` extends Screen, can call these methods. UI can request scan through world().scan(center, radius<=32, vertical<=16); scan on demand only. Registration must pause automation. Never include server address/coordinates in tracked defaults or diagnostics uploaded to GitHub.
