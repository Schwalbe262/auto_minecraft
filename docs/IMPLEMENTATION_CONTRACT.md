# Shared implementation contract

Package: `dev.schwalbe.autovalley`. Java 17, Forge 1.20.1 / 47.4.0.
Root owns `core/`, `client/` adapter/runtime, build files, safety, profile persistence, documentation and release scripts.
Navigation agent owns `navigation/`, `modules/HarvestModule.java`, navigation/harvest tests.
Logistics agent owns other `modules/` and logistics tests (including SleepModule).
UI agent owns `ui/` and `assets/autovalley/lang/` only.

Core APIs are source of truth in `core/`. Ask root before changing them.
Everything runs once per client tick. Modules never access Minecraft directly: use Context.
Context.checkpoint is a synchronous persistence boundary in the live runtime; compatibility test constructors use an explicit no-op. Mature machine Use must follow MachineOutputLedger.prepare/checkpoint and separate machine-confirmation/pickup checkpoints. Profile schema 2 retains pending output and bounded resolution history; live evidence belongs to SessionState only and is invalidated by manual item interaction or reconnect. F8/reset must never clear the persistent ledger.
ActionPort submit returns ticket; poll outcome on subsequent ticks. One pending action at a time. Do not repeat an action until acknowledged. Cancel requires immediate silence, no cleanup clicks. All world attack/break commands are absent.
Inventory indices 0..35 match Player inventory. Menu ItemSlot.index is actual menu slot, inventoryIndex refers to Player inventory if player=true, -1 otherwise. world.menu() always returns inventory menu when no container is open, with container=false. Only player inventory entries 0..35 are exposed via world.inventory().
SelectHotbar and SwapHotbar allow moving ingredients to held slot without a cursor transaction. QuickMove uses standard shift-transfer and verifies state change. Do not depend on unopened chest contents, server persistentData, or unsynced machine fields.
ConsolidateInventory accepts only a freshly revalidated ProductionMergePlanner plan, with no pending machine output. It is owned-inventory-only; QuickMove remains container-only. Native adapter owns the bounded primitive sequence and returns quantity as actual freed slots, not moved item count. A reposition plan can validly return zero freed slots. No-op attempts must be bounded using a position-independent inventory fingerprint. Cancel sends no cleanup clicks; ActionPort.pauseReason/startRejection fence unresolved late replies and pause all scheduler consumers. Reconnect clears transient layout uncertainty, not persistent output obligations. Native ACK item/cursor snapshots remain RAM-only and must not leak into diagnostics/recordings.
After an exact primitive ACK, a subsequent raw server slot packet may refresh an unrelated baseline slot without advancing the transaction. Every changed slot must exactly match its latest post-ACK packet item; the packet observer's applied client menu is not authoritative evidence. Only production-item additions or exact installed-Vinery passive metadata updates qualify. Source, borrowed hotbar, protected hoe, and the next QUICK_MOVE's entire implicit receiving region remain exact. This refresh cannot confirm, repeat, skip, or restore an unacknowledged click. The remaining RESTORE still needs its own exact full-menu ACK.
UseBlock(MACHINE) checks actual block state and inventory decrease; products may drop. Modules must separately wait for pickup before declaring harvest success. UseBlock(HARVEST) verifies mature state change; native tomato age=3. UseBlock(OPEN_CONTAINER) waits for new synchronized container. Only normal main hand useItemOn, no air-use fallback. Range and visibility checked by adapter.
Profile POIs are individually confirmed. classifier: production Year for WINE_CHEST; null for TOMATO_CHEST and others. Legacy tomato grade values and desired-layout targets are inert, not permissions or routing rules. Tomato warehouses accept only the tomato commodity, with mixed grades allowed; actual per-grade stock still determines production input. Native stacking never combines incompatible grades/tags. Wine cohort restrictions are unchanged. Farms are two corner inclusive bounds (include vines at both heights), cap volume 32768. Waypoints record walkable feet positions and form connected approved corridors. Poi DISPOSAL marks player standing position when registered, not a block to interact with.
Production grade choice is batch-based, not live balancing. Use carried ingredients before another stock survey; a supply trip freshly counts actual grades and allocates the largest total, then keeps that batch while usable. Neither a short cache TTL nor grade crossover should trigger a trip while carried material remains usable. Source reopen and native transfers still verify actual contents. Storage visit ordering completes each same-kind face-adjacent component before visiting the next; it grants no new registrations or movement permissions.
Wine scheduling uses one durable whole-rack cycle, not independent due-machine trips. Legacy registration deadlines migrate to their maximum. A due cycle opens only after a read-only readiness check of the entire registered rack; unfinished working machines defer the whole run without navigation or stock scans. Persist the active remaining list and remove a target only after native refill confirmation. Manual stop/reconnect must retain unfinished work. The last confirmed feed day anchors the next common deadline. Explicit schedule reset and clock rollback reset both per-target dates and the global cycle; storage wine-age classification is a separate clock and remains unchanged.
Harvest prioritizes 50; logistics 10..40; wine 60 before preserves 70; sleep 100. A BUSY module owns the scheduler until IDLE/BLOCKED, or cancellation. IDLE means nothing actionable, BLOCKED is user-actionable failure and prevents automatic sleep that cycle. Resource shortages in continuous mode and processing machines are IDLE, not BLOCKED. An unfunded eligible refill in one-shot mode is BLOCKED and must remain retryable on the same day. Disabled modules receive no tick and any active module is cancelled on toggle. Sleep time uses dayTime modulo 24000 >=12584, actual next day observed.
Client facade for UI (root will implement): `ClientRuntime.instance()`, `.profile()`, `.world()`, `.status()` string, `.running()` boolean, `.toggle()`, `.pause(String)`, `.saveProfile()`, `.toggleFeature(Feature)`, `.startCalibration()`; `openSettings()` from root handles GUI. UI entry `new ValleyScreen()` extends Screen, can call these methods. UI can request scan through world().scan(center, radius<=32, vertical<=16); scan on demand only. Registration must pause automation. Never include server address/coordinates in tracked defaults or diagnostics uploaded to GitHub.
