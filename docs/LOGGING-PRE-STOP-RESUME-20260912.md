# 벌목 중 직접 조작 후 F8 재개

## 실제 원인

2026-09-12 04:30 KST 네이티브 진단에서 벌목 진행률 약 0.633,
`started=true`, `stopped=false`, `aborted=true`인 취소된 채굴이 남아 있었다.
이 동작은 STOP 전에 취소되어 성공적인 벌목 응답이 오지 않을 수 있는데,
기존 재개 제한은 성공 응답만 기다렸다. 따라서 정상적인 직접 조작 일시정지가
재접속 없이는 재개되지 않는 상태를 만들 수 있었다.

## 수정 범위

- 해당 ABORT 패킷 자체가 실제로 전송되고, 같은 연결의 서버 처리 ACK가 그
  패킷 순번까지 처리했음을 확인한 경우에만 STOP 이전 취소 대기를 해제한다.
- 호출자의 `send()` 반환이나 시간 경과만으로 해제하지 않는다. 쓰기 억제·실패,
  다른 패킷, 이전 연결의 ACK는 근거가 되지 않는다.
- STOP 이후에는 서버가 지연 파괴를 진행할 수 있으므로 같은 규칙을 적용하지
  않는다. 즉시 파괴 및 묘목 심기도 이 취소 증명에서 제외한다.
- 실제 성공 응답은 수신 시 연결별로 기억한다. OFF 중 응답이 도착하거나 원시
  기록에서 오래된 응답이 빠져도 이미 확인한 성공 근거를 잃지 않는다.
- 취소된 작업을 성공 처리하지 않으며, 남은 벌목·재식재·단축바 반환 기록을
  삭제하지 않는다. 자동으로 사용자 일시정지를 해제하지도 않는다.

설치된 Forge 47.4.0 및 TreeChop 0.19.0-fixed의 실제 동작을 확인해 적용 범위를
제한했다. 서버 처리 ACK는 Forge가 ABORT를 허용했다는 뜻과는 다르다.
이 경우의 근거는 STOP 이전의 일반 채굴이 이후 파괴를 예약하지 않는다는 점이다.
