# 결정생성기: 옥 고정 제거 / 수동 재료 투입

> 이전 구현의 기록이다. 회수 전용 정책은 사용자의 재투입 요청에 따라
> [기계별 동일 원본 자동 재투입](CRYSTAL-SAME-ORIGIN-20260911.md)으로 대체된다.

## 동작

- 결정생성기 10개 등 등록된 좌표만 사용한다. 주변의 다른 기계나 보관함을 임의로 등록하지 않는다.
- `CRYSTAL_COPY`는 기존 `jade_crystal` 등록까지 포함하여 **빈손 회수 전용**이다. 자동 재료 조사·인출·투입·교체를 하지 않는다.
- 사용자가 수동으로 넣은 종류의 완성품을 회수한다. 지원되는 56종을 구별하며, 옥이 들어온다고 가정하여 옥 수량을 기다리지 않는다.
- 하루에 한 번 등록 기계의 상태를 확인한다. `mature=true, working=false`인 기계만 클릭하고, 작업 중이거나 빈 기계는 건너뛴다. 이것은 생산 주기가 아니라 **상태 확인 주기**다.
- 회수 후 다음 기계로 진행한다. 옥을 비롯한 결정이 인벤토리에 있어도 재투입하지 않는다.
- 실제 서버의 해당 기계 완료 응답과 완성품 증가 확인을 유지한다. 시간 초과·연결 변경·미확인 조작은 성공으로 간주하지 않는다.

## 설치본의 실제 제약

Society Sunlit Valley 4.1.4의 다음 로컬 소스로 확인했다.

- `kubejs/startup_scripts/customMachines/crystalarium.js`: 원본 56종, 같은 종류 2개 산출. 종류에 따라 1~6일. 업그레이드 기계는 별도 pristine 보너스를 낼 수 있다.
- `kubejs/startup_scripts/globalBlockEntityHandlers.js`: 회수는 `data.recipe`를 지우고 기계를 비운다. 재료를 든 우클릭은 회수 후 새 재료를 1개 소비한다. 따라서 빈손 회수만으로 자동 재생산되지는 않는다.
- 클라이언트의 일반 블록 엔티티 데이터만으로 내부 recipe가 동기화되었다고 가정하지 않는다.

현재 구현은 사용자의 “원본은 수동으로 넣겠다”는 요청에 맞춰 회수·보관만 자동화한다. 처음 지정한 종류를 계속 자동 재투입하는 방식은 별도의 선택이며, 이번 변경에서 추측하여 실행하지 않는다.

## 보관과 호환

- 최초 자동 등록 형태가 그대로인 `jade_crystalariums` / `jade_stock`만 다음 프로필 로드 때 일반 결정 회수 작업으로 전환한다.
- 기존 보관함 좌표는 그대로 두고, 표시 이름을 `결정생성기 산출물 보관함`, 허용 품목을 기본 결정 56종으로 변경한다. 옥을 제외하거나 기존 물건을 삭제하지 않는다.
- 사용자가 이름·품목을 바꾼 보관함, 다른 작업이 공유하는 보관함은 자동 확장하지 않는다. 별도 등록된 저장 품목은 계속 존중한다.
- pristine 보너스는 인식하되 보관 품목에 명시되지 않았다면 인벤토리에 남긴다. 자동 판매·폐기는 하지 않는다.
- 별도 `crystal-inspection:` 일정 키를 사용한다. 예전 옥 5일 생산 날짜를 다른 원본에 적용하지 않으며, 기존 일정 기록·다른 작물/와인 주기·기능 ON/OFF는 변경하지 않는다.
- 결정 산출물은 임시 단축바 원본으로 빌리지 않는다. 기존 단축바 보관·복원 ACK와 다른 작업의 권한 제한은 유지한다.

## 검증과 배포

- `gradle --offline test build` 통과: 전체 2,467개 테스트, 실패·오류 0개.
- 정책·혼합 품목 회수·재투입 금지·일정·저장 권한·단축바 복원·프로필 마이그레이션 회귀를 포함한다.
- 수거물로 빌린 빈손 칸이 차면, 그 결정만 일반 인벤토리 빈칸으로 옮기고 실제 SWAP ACK를 받은 뒤 다음 통으로 진행한다.
- 실제 오버월드 프로필을 읽기 전용 검증했다: 등록 기계 10개, 기존 보관함 1개, 일반 결정 56종으로 정상 변환된다. 원본 파일 바이트는 변경하지 않았다.
- 설치 호환성 검사 통과. 빌드 JAR SHA256: `4DC630E10DB55C0FFB46B046D5B36B46356ED42F673188C6AA967F9E350D11A1`.

이번 작업에서는 빌드·오프라인 검증까지만 완료했다. 실행 중인 게임에 설치·재시작·실제 회수 테스트는 하지 않았다. 게임에 적용하려면 빌드된 모드의 설치와 기존 인스턴스 재시작이 필요하다. 수동 플레이 중인 게임을 이 변경만으로 자동 재개하거나 새 인스턴스를 열지 않는다.
