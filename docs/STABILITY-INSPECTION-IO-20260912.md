# 장시간 관측 중 진단 파일 읽기 경합

## 확인한 현상

최종 CD84 게임 빌드 관측 중 13:35:13, 13:41:42 KST 표본에서
`STALE_DIAGNOSTIC_PROCESS_ALIVE`가 기록됐다. 이후 동일 게임 프로세스의
최신 ON 상태를 다시 받았다. 첫 공백과 겹치는 13:35:03 로그에는
`Auto Valley local inspection failed once: AccessDeniedException`이 있었다.
예외 로그에는 연산·경로가 없어 그 사건의 직접 원인을 단정하지 않는다.

실제 게임의 JDK 17.0.15와 별도 임시 파일로 다음 경합을 재현했다.
PowerShell `Get-Content -Raw` 읽기가 열린 동안 Java의
`Files.move(ATOMIC_MOVE, REPLACE_EXISTING)`는 접근 거부로 실패하고,
읽기가 끝난 뒤에는 성공했다. `FileShare.ReadWrite | Delete`를 지정한
대조군도 열린 동안 실패했다. 따라서 공유 플래그 추가만으로 해결됐다고
주장하지 않는다. 게임 파일이나 기존 게임 프로세스는 실험에 사용하지 않았다.

## 관측기만 변경

- 요청 전에는 파일 수정 시각·크기만 확인한다. 오래된 진단 본문을
  250ms마다 반복해서 열지 않는다.
- 요청 이후 수정된 새 후보만 메타데이터 버전별 1회 읽는다.
- 본문 읽기를 끝내 파일을 닫은 뒤 JSON을 해석한다.
- 실제 `capturedAt`, 이전 수신 시각, 미래 시각, 정확한 PID·시작 시각,
  파일 크기·링크 검사, 제한시간, 단일 요청 및 안정화 판정은 유지한다.
- 잘못된 후보를 정상으로 간주하지 않는다. 일시적 읽기 오류 역시 같은
  버전을 반복해서 열지 않으므로 여전히 조회 실패로 끝날 수 있다.

게임 코드·JAR·설정은 변경하지 않는다. 관측기를 교체하더라도 이전 파일과
조회 공백은 보존하며, 공백이 없는 연속 실행으로 소급 판정하지 않는다.

## 검증

`Test-SocietyStability.ps1`: 기존 37개와 신규 17개, 총 54개 통과.
변경 없는 본문 0회, 새 후보 1회, 동일 크기 교체, 수정 시각만 바뀐 과거 응답,
미래·중복·잘린 응답 거부, 다음 정상 버전 수락, 크기·링크·디렉터리 및
후보 읽기 후 PID 교체 거부, 요청 파일 재작성 방지를 검사한다.
이는 격리된 관측기 테스트이며 게임의 2시간 안정화 검증을 대신하지 않는다.

13:56 현재 게임 관측에서는 벌목 배치 2회 종료와 게임 날짜 769→773을
확인했다. 계단 이동 실패 1회가 기록됐지만 전체 OFF는 관측되지 않았다.
토마토 1,224개가 사라지고 지하층으로 이동한 것은 처리 진행의 간접 증거이며,
해당 보관함의 입고 응답 자체를 확보한 것으로 주장하지 않는다.
다음 실제 수확·보관과 최소 2시간의 관측은 계속 진행 중이다.
