# 결정생성기: 같은 원본으로 자동 재투입

## 변경 이유

“원본은 직접 넣겠다”는 요청을 자동 재투입도 하지 않는 것으로 해석한 이전 구현은
완성품만 회수하고 기계를 비웠다. 사용자가 선택한 품목을 계속 복제하도록 수정한다.
옥 고정 레시피나 인벤토리에 우연히 들어온 다른 결정으로 원본을 추정하지 않는다.

## 동작

- 등록된 기계에 접근해 **회수 전에** 실제 Jade 서버 응답의 `recipe`를 읽는다.
- 기계마다 확인된 원본을 사용한다. 불의 석영 기계에는 불의 석영 1개만 넣는다.
- 같은 결정이 손에 있으면 한 번의 우클릭으로 회수·재투입한다. 없다면 빈손으로
  회수한 뒤 같은 종류의 수거물에서 1개를 재투입한다. 산출물은 기본 2개, 순증은 1개다.
- 회수 직전 원본·기계·작업을 프로필에 먼저 저장한다. OFF/ON·재시작 뒤에도
  해당 기계의 재투입을 이어갈 수 있다. 이는 재개 의도이며 과거 클릭의 성공 증거가 아니다.
- 실제 투입 응답 확인 후 원본별 1~6일 주기를 예약하고 재투입 기록을 원자적으로 지운다.
  불의 석영은 2일이다. 기존 옥 5일 레거시 일정은 다른 결정에 적용하지 않는다.
- 중단 후 기계가 이미 가동 중이면 새 서버 원본 조회로 이를 확인해 재클릭하지 않는다.
- 원본을 직접 바꾸면 다음 조회에서 새 원본을 따른다. 원본 정보가 없는 빈 기계는
  임의로 채우지 않는다. 원본 조회 실패·재료 부족은 해당 기계를 보류한다.
- 보관 품목은 기존 등록을 존중한다. 미등록 pristine 보너스를 자동 판매·폐기하지 않는다.

## 원본 관측과 변경 권한

설치된 Society 4.1.4의 `crystalarium.js`, `globalBlockEntityHandlers.js`,
`registerJadeData.js` 및 Jade 11.13.2 Forge 프로토콜 2를 기준으로 했다.
일반 클라이언트 블록 엔티티에는 원본이 동기화된다고 가정하지 않는다.

- 보통 Jade 툴팁 요청을 사용한다. 조회 자체는 클릭·시야·단축바·인벤토리를 변경하지 않는다.
- 서버 응답에서 정확한 좌표, 결정생성기 엔티티 타입, 지원 원본을 확인한다.
  이후 빈 값·미지원 응답은 이전 양성 관측을 무효화한다.
- 접속 세대, 요청 이후 관측 순서, 블록 상태, 100틱 유효기간을 검사한다.
  수동 조작·OFF·대상 변경 시 관측을 폐기한다.
- Jade 프로토콜에는 요청 nonce나 차원이 없다. 완전한 RPC 상관관계를 주장하지 않으며,
  같은 세대·좌표에서 늦게 도착한 응답을 구별하는 데에는 이 프로토콜의 한계가 있다.
- 실제 우클릭은 기존 블록·선택 슬롯 서버 ACK 검증을 그대로 사용한다.
  원본 조회가 과거 미확인 클릭의 성공 증거를 대신하지 않는다.
- 빈 기계에 투입하려면 해당 작업·좌표의 저장된 재투입 원본과 새 빈 상태 조회가 모두
  필요하다. 저장고에서도 이 재투입 원본만 인출할 수 있다.
- 새 재투입 기록은 프로필 스키마 8이다. 저장 실패는 기록·스키마·일정을 롤백한다.
  이전 클라이언트가 새 기록을 무시하고 실행하지 않도록 미래 스키마 거부를 유지한다.
