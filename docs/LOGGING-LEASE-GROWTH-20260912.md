# 벌목 중 임시 단축바 수량 증가로 인한 중단

## 확인된 현상

2026-09-12 03:41 KST 읽기 전용 진단에서 게임은 연결되어 있었지만 연속 자동화는 OFF였다.
최초 벌목 실패는 임시 단축바 원본을 확인할 수 없다는 오류이며,
그 뒤 재시작 시도에서도 같은 복원 기록 때문에 12번 중단이 누적되어 있었다.

- 저장된 `loggingHotbarLease`: `PARKED`, 원본 `meadow:fire_log` 6개.
- 실제 원본 보관 슬롯: `meadow:fire_log` 9개.
- 임시 단축바 슬롯: 가문비나무 묘목 14개.
- 커서는 비었고 일반 인벤토리였다. 작업 공간 부족이나 서버 연결 종료가 아니었다.

수량 증가의 원인을 단순히 자석·줍기 또는 수동 조작 중 하나로 단정하지 않는다.
확인된 결함은 `NativeLoggingSwap`이 동일 네이티브 아이템의 수량 증가를 포함한
실제 교환 응답을 인정하는 반면, 영속 벌목 임대 기록은 최초 수량을 그대로 유지한다는 것이다.
`LoggingModule.parked()`는 최초 수량과 지문을 정확히 비교하므로, 보존된 같은 원본이
증가해도 복원 불명확으로 처리하고 전체 자동화를 중지한다.

## 수정 원칙

원본 기록을 지우거나 현재 슬롯만 보고 교환 성공을 조작하지 않는다.
실제 최신 서버 인벤토리 응답으로 원본의 네이티브 품목·태그가 그대로이고
수량만 증가했다는 것을 확인한 경우에만 원본 수량과 지문을 함께 저장한다.
저장 실패는 원래 임대 기록으로 복구하며, 그 뒤 기존 정확한 복원 절차를 따른다.

태그 변경·다른 품목·수량 감소·커서 점유·불명확한 교환은 이 예외로 처리하지 않는다.
게임 조작을 재전송하거나 과거 미확인 응답을 성공으로 간주하지 않는다.

돌아간다. 등록 및 미완료 의무의 변경, 미확인 네이티브 조작은 여전히 거절하며,

관련 반복 언로드·지형 변경·서버 벌목 거절 회귀 테스트를 포함한다.

처리한다. 착지 전에 교환을 재전송하거나 오래된 수량 때문에 실패 처리하지 않는다.

### 재접속 후 별도로 확인된 상태

04:03–04:04 KST 새 진단에서는 원래 단축바와 보관 슬롯이 둘 다 비었고,
기존 묘목은 다른 인벤토리 슬롯에 있었다. `meadow:fire_log`는 일반 인벤토리에
없었으며, F8 시작 후에는 남아 있는 동일 복원 기록 때문에 다시 중단됐다.
수량 증가 확인은 아이템 부재를 복원 완료로 간주하지 않으므로 이 상태는 별개다.
외부 인벤토리 정리 여부는 사용자에게 확인 요청했다.

이에 기존 일반 작업의 명시적 수동 정리 확인 기능을 벌목에도 확장한다.
현재 기록의 품목·수량·위치·지문·단계에 묶인 별도 확인을 받은 경우에만
단축바 반환 기록을 감사 이력으로 옮긴다. 미완료 구역·재식재·주기와 실제 아이템은
변경하지 않으며, 자동화를 시작하거나 미확인 서버 조작을 성공 처리하지 않는다.
F8 및 단순 아이템 부재는 수동 확인을 대신하지 않는다.
사용자가 해당 단축바 반환 의무만 해제하는 절차를 설명받고 해결을 위임했다.
