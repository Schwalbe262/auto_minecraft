# 수동 정리 후 자동화 시작 복구

## 원인

사용자가 화염석을 이미 직접 정리했지만, 결정복제기 작업의 이전 `PARKED` 임시 단축바 복원 기록이 남아 있었다. 재발 방지 코드를 설치하고 게임을 재시작한 것만으로는 이 기록이 해제되지 않는다. 일반 시작은 먼저 원본 복원을 시도하므로 원래 수량·지문과 일치하는 아이템을 찾지 못해 다른 루틴에 진입하지 못했다.

## 재사용 가능한 확인 절차

- `Ctrl+F8 → 실행·기록 → 임시바 수동 정리 완료`에서 대상 품목·수량·칸을 확인한 뒤 별도 화면의 최종 확인 버튼을 누른다. 실제 수동 정리를 마친 경우에만 사용한다.
- 확인은 아이템을 이동하지 않는다. 기존 복원 의무를 `CONFIRMED_MANUALLY_HANDLED` 이력으로 보관하고, 별도 F8 시작을 허용한다. 확인 자체는 자동화를 켜지 않는다.
- 대상 기록의 모든 필드를 묶은 SHA-256 확인 키를 검사한다. UI는 선택한 프로필과 기록도 다시 검사한다. 이전 확인 이력만으로 새 기록을 자동 해제하지 않는다.
- 자동화·녹화 OFF, 정상 인벤토리와 빈 커서, 연결·지상 상태, 조용한 네이티브 조작 상태에서만 가능하다. 미확인 클릭·늦은 응답·다른 복원/산출물 의무가 있으면 거부한다.
- 가드는 읽기 전용이다. 기존 `startRejection()`이나 `pauseReason()`을 호출해 네이티브 응답을 정산하거나 실패를 지우지 않는다. 과거 작업을 성공으로 바꾸지 않는다.
- 기존 프로필 저장 경로로 이력과 기록 해제를 함께 저장한다. 실패하면 원래 기록·이력·세션 소유자·스키마를 복원한다. 이력은 최근 32건으로 제한한다.

로컬 제어에도 동일한 검사와 저장 경로를 사용하는 `confirm_work_hotbar` 명령을 추가했다. `command`와 정확한 소문자 64자리 확인 키인 `name`만 받으며, 알 수 없는 필드·중복 필드·잘못된 키를 거부한다. 자동 시작은 별도 `start` 명령이다.

## 검증 범위

회귀 테스트는 실제 스케줄러가 기존 기록 때문에 시작에 실패하는 경우부터, 명시적 확인 후 별도 시작으로 일반 모듈에 진입하는 과정까지 검증한다. 오래된 키, 남은 네이티브 응답, 저장 실패, 설정/일정/인벤토리 불변, 이력 재로딩과 잘못된 이력 거부도 포함한다.

이 절차는 명시적으로 수동 정리를 확인하는 복구 경로다. 정상 작업에서 임시바 문제가 재발하지 않도록 하는 결정 품목 제외·작업 칸 비우기·최신 슬롯 관측 수정은 기존 변경을 유지한다.
